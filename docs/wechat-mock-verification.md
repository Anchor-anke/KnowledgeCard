# 微信开发者工具 Mock 验证

当前仓库已经增加一个原生微信小程序 Mock 客户端，用于验证卡片学习、批量复习和完成界面。它不调用真实微信登录、真实 API 或真实订阅消息，数据保存于开发者工具本地缓存。

该 Mock 当前仍使用内置 CAPM 演示卡片，不包含用户 PDF 上传、PDF 解析或真实 AI 生成；这些能力在 [`user-pdf-import.md`](./user-pdf-import.md) 中定义，属于后续实现范围。

## 导入项目

1. 安装并打开微信开发者工具。
2. 选择“导入项目”。
3. 项目目录选择仓库根目录：

   `/Users/anchorxia/KnowledgeCard`

4. 开发者工具会读取根目录的 `project.config.json`，并将 `miniprogram/` 作为小程序根目录。
5. AppID 可以先使用测试号；正式接入时替换为真实小程序 AppID。

## 推荐验证流程

1. 首次打开进入品牌欢迎页。
2. 进入新手教学，确认第一张教学卡需要上滑开始。
3. 在教学卡中确认上滑下一张、下滑返回、左右滑动移除当前卡的逻辑。
4. 教学完成后进入“知识库”选择页，确认 CAPM 全部知识及各 Domain 内容均显示独立学习进度。
5. 选择一套学习内容，进入学习页查看第一张卡。
6. 左右滑动卡片，确认自动提交“没记住”，并安排 10 分钟后复习。
7. 手指从下往上滑，确认进入下一个知识点但暂不提交“记住了”；手指从上往下滑，确认返回上一个知识点但暂不提交“记住了”。
8. 左右滑动的卡片应立即提交“没记住”并从当前学习组移除。
9. 完成整组卡片后，确认剩余待确认卡片一次性提交“记住了”，并显示本组完成反馈。
10. 在设置页点击“模拟产生到期复习”，返回知识库确认对应内容显示待复习数量。
11. 点击“反馈”，确认卡片问题可以提交。
12. 切换订阅消息开关，确认拒绝授权不会阻断学习。
13. 点击“重置 Mock 学习数据”，重新开始流程。

## Mock 与真实服务的边界

Mock API 位于 `miniprogram/utils/mock-api.js`。它保持了未来 HTTP API 的主要方法边界：

- `getSession`
- `completeOnboarding`
- `getLibrary`
- `setActiveDeck`
- `getLearningEntry`
- `completeCard`
- `submitRating`
- `requestSubscription`
- `submitFeedback`

接入真实后端时，只需要将这些方法替换为 `wx.request` 调用，不应在页面中直接修改学习计划或卡片数据。
