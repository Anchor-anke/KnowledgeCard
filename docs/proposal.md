# CAPM 学习小程序需求文档

> 文档状态：MVP 需求提案  
> 版本：v0.1  
> 更新时间：2026-07-13  
> 产品形态：微信小程序  
> 首版认证范围：PMI CAPM（Certified Associate in Project Management，项目管理助理认证），中国地区  
> 主要内容依据：[PMI CAPM 考试大纲](https://www.pmi.org/-/media/pmi/documents/public/pdf/certifications/capm-exam-content-outline-english.pdf?rev=384b8325cd60488abbb4e148a9652ffc&la=zh-cn)

## 1. 产品概述

### 1.1 产品愿景

打造一款让备考者像刷短视频一样，利用碎片时间高效吸收并长期记忆 CAPM 知识点的沉浸式学习工具。

产品不以“看过多少内容”为主要价值，而是通过短小、清晰的知识卡和持续的间隔复习，把一次浏览转化为可回忆、可保持的知识。

### 1.2 核心问题

当前备考者通常面临以下问题：

- 学习资料篇幅长、结构复杂，很难在碎片时间开始学习。
- 被动阅读容易产生“看懂了”的错觉，但无法在考试中主动回忆。
- 用户不知道什么时候应该复习哪些知识点，复习容易中断。
- 高质量内容制作需要教研人员投入大量时间，难以快速覆盖完整考试大纲。

### 1.3 产品价值

| 目标 | 产品价值 |
| --- | --- |
| 抓住注意力 | 用单张卡片承载一个清晰知识点，通过上下滑动降低开始学习的阻力 |
| 提升学习效果 | 根据用户自评安排间隔复习，把浏览行为转化为长期记忆 |
| 提高内容供给效率 | 用 AI 完成知识拆解、卡片初稿和回忆题生成，由人工审核后发布 |

## 2. 用户与使用场景

### 2.1 首版目标用户

首版用户为准备参加中国地区 PMI CAPM 认证考试的备考者。

产品未来可以扩展到其他认证考试，但不纳入首版内容和功能验收范围。

### 2.2 典型使用场景

1. 用户在通勤、排队或休息时打开小程序。
2. 用户通过新手引导选择学习目标，并进入知识卡流。
3. 用户在约 30 秒内理解一张卡的核心内容。
4. 用户继续上滑浏览下一张卡。
5. 系统在合适时间让用户对已学知识点进行复习。
6. 用户复习后选择“忘了”“模糊”或“记住了”，系统据此安排下一次复习。

## 3. MVP 目标与成功标准

### 3.1 MVP 目标

- 验证用户是否愿意通过短卡片开始 CAPM 学习。
- 验证上下滑动的连续学习方式是否能降低学习阻力。
- 验证自评驱动的间隔复习是否能促使用户持续回来复习。
- 验证 AI 辅助、人工审核的内容生产流程是否能稳定产出可发布卡片。

### 3.2 成功标准

首版重点观察以下指标，不预先设定具体数值，目标值待产品负责人根据测试规模确定：

- **首次激活率**：首次进入小程序的用户中，完成新手引导并开始浏览第一张卡的比例。
- **知识点完成率**：用户开始学习的知识点中，完成规定卡片学习流程的比例。
- **复习留存率**：用户在出现复习任务后，按期返回并完成复习的比例。
- **连续学习行为**：用户是否会在一次会话中连续完成多张卡片。
- **内容质量反馈**：卡片被用户标记为错误、难懂或重复的比例。

考试通过率属于长期效果指标，在拥有足够样本和合规的用户反馈机制后再评估，不作为 MVP 上线前的唯一验收条件。

## 4. MVP 范围

### 4.1 必须包含

- 微信授权登录。
- 新手引导和学习目标设置。
- 上下滑动知识卡流：上滑下一张，下滑上一张。
- 单张卡片的核心知识点展示。
- 用户自评：忘了、模糊、记住了。
- 根据自评结果生成间隔复习任务。
- 复习任务列表或入口。
- 微信订阅消息复习提醒。
- 基础内容管理能力：编辑、审核、发布、下架。
- AI 辅助内容生产：知识点拆解、卡片初稿、回忆题生成。

### 4.2 暂不包含

以下内容不属于本次 MVP 的交付范围：

- 多认证、多学科的完整内容体系。
- 用户自主创建并公开发布卡片。
- 社区、评论、关注、排行榜等社交功能。
- 付费订阅、课程商城和广告系统。
- 全量题库、模拟考试和复杂考试分析。
- 个性化搜索、复杂推荐算法和社交分享增长体系。
- AI 生成内容未经人工审核自动发布。

## 5. 核心用户流程

### 5.1 首次学习流程

1. 用户打开小程序。
2. 用户通过微信授权登录。
3. 用户查看产品价值和使用方式。
4. 用户设置或确认 CAPM 学习目标。
5. 系统进入首个学习任务。
6. 用户浏览知识卡。
7. 用户完成卡片后进行记忆自评。
8. 系统记录学习结果并安排后续复习。

### 5.2 日常学习流程

1. 用户进入小程序。
2. 系统优先展示待复习内容；若没有到期内容，再展示新的知识卡。
3. 用户上下滑动浏览卡片。
4. 用户在卡片学习完成后选择记忆程度。
5. 系统更新该知识点的复习计划。
6. 用户可以继续学习，或结束本次学习。

### 5.3 复习流程

1. 系统依据知识点的复习计划识别到期任务。
2. 小程序内展示待复习任务。
3. 用户重新查看知识卡，并完成回忆提示或自评。
4. 用户选择“忘了”“模糊”或“记住了”。
5. 系统保存本次复习结果，计算下一次复习时间。
6. 如果用户允许订阅消息，系统在到期时发送提醒。

## 6. 功能需求

### 6.1 微信登录与用户身份

**目标**：让用户能够跨设备保存学习进度。

**需求**：

- 支持微信授权登录。
- 首次登录时创建用户学习档案。
- 保存用户的学习目标、学习记录、自评结果和复习计划。
- 未授权订阅消息时，不能发送微信订阅提醒，但不影响用户在小程序内复习。
- 登录、学习记录和提醒相关数据需要遵守适用的隐私和数据保护要求。

### 6.2 新手引导

**目标**：让用户在首次使用时理解产品，并快速开始第一张卡。

**需求**：

- 用简短页面说明“短卡片 + 间隔复习”的学习方式。
- 让用户确认 CAPM 学习目标。
- 引导用户理解三种记忆自评选项。
- 引导用户授权微信订阅消息；用户可以拒绝。
- 引导结束后直接进入学习卡流，不要求用户先完成复杂设置。

### 6.3 知识卡流

**目标**：实现“30 秒看懂一张卡”的低阻力学习体验。

**交互约定**：

- 上滑进入下一张卡片。
- 下滑返回上一张卡片。
- 单张卡片围绕一个知识点组织内容。
- 卡片应优先展示结论、关键词和必要解释，避免大段教材原文。
- 卡片内容需要适合手机纵向阅读。
- 当用户完成当前卡片的阅读或回忆步骤后，展示记忆自评。
- 用户可以结束本次学习，不能因误触导致学习结果被静默记录。

**卡片内容建议结构**：

1. 知识点标题。
2. 一句话结论。
3. 关键解释或步骤。
4. 一个帮助理解的例子、对比或注意事项。
5. 一个回忆提示或自测问题。
6. 来源和内容版本信息。

“30 秒”是体验目标，不代表所有知识点必须严格限制在固定字数或固定阅读时长；复杂知识点需要拆成多张有前后关系的卡片。

### 6.4 记忆自评

**需求**：

- 每张新卡或复习卡完成后，展示三个明确选项：
  - **忘了**：无法回忆核心内容。
  - **模糊**：能想起部分内容，但不稳定或不完整。
  - **记住了**：能够较完整地回忆核心内容。
- 用户选择后立即给出轻量反馈，并进入下一张卡或复习任务。
- 系统保存卡片、用户、时间和自评结果的关联记录。
- 自评结果必须可以被用户修改或重新进行，避免误触造成长期错误排期。

### 6.5 间隔复习

**目标**：在用户即将遗忘之前安排复习，减少“刷完就忘”。

**MVP 要求**：

- 每个知识点维护独立的学习状态和下一次复习时间。
- 新卡完成后进入复习计划，而不是仅标记为“已看过”。
- “忘了”“模糊”“记住了”对下一次复习时间产生不同影响。
- “忘了”应缩短下一次复习间隔或重新进入较早阶段。
- “记住了”应在连续稳定回忆后逐步拉长复习间隔。
- 到期任务优先于全新内容展示，避免用户只消费新卡而跳过复习。
- 同一知识点的多次复习记录需要可追踪。
- 算法的具体名称、初始间隔、间隔增长规则、时区和错过任务后的处理方式在技术设计阶段确定，并通过学习数据验证。

**待确认的算法决策**：

- 首版采用哪一种具体算法或规则实现。
- 三档自评与间隔长度的精确映射。
- 用户错过多个复习任务时，是补齐全部任务还是合并为一次复习。
- 是否允许用户调整每日学习量和提醒时间。

### 6.6 复习提醒

**需求**：

- 使用微信订阅消息发送到期复习提醒。
- 在用户首次使用或合适的操作节点请求订阅授权，不能默认视为用户已授权。
- 提醒内容至少包含待复习提示和进入小程序的路径。
- 用户拒绝订阅后，仍可在小程序内看到待复习任务。
- 发送频率、提醒时间和同日多任务合并规则待确认。

## 7. 内容生产与管理

### 7.1 内容原则

- 首版内容以 CAPM 官方考试大纲为边界，不声称替代 PMI 官方教材、课程或考试。
- 每张卡只解决一个明确的知识目标。
- 内容应区分定义、流程、原则、比较、应用和易错点等类型。
- 卡片必须标注来源、版本和审核状态。
- 不直接复制未经授权的教材、题库或其他受版权保护内容。

### 7.2 AI 辅助生产流程

1. 内容人员提供官方大纲、已获授权的参考资料或结构化知识输入。
2. AI 按主题和知识目标拆解知识点。
3. AI 生成卡片初稿，包括标题、结论、解释、例子和回忆题。
4. AI 对内容进行基础检查，如重复检测、结构完整性和难度提示。
5. 教研人员核对事实、术语、范围、版权和考试适配性。
6. 教研人员编辑并提交审核。
7. 审核通过后发布到用户端。
8. 发现错误或资料变更时，可以下架并保留版本记录。

AI 只能生成和辅助检查内容，不能在 MVP 中绕过人工审核直接发布。

### 7.3 基础内容管理后台

首版后台只需覆盖基本生产闭环：

- 新建、编辑和保存草稿。
- 录入或导入知识点来源。
- 触发 AI 生成卡片初稿和回忆题。
- 查看并修改 AI 输出。
- 提交人工审核。
- 审核通过、驳回并填写原因。
- 发布、下架和恢复卡片。
- 查看卡片版本、来源和审核记录。
- 按主题、状态和版本筛选内容。

后台角色和权限的详细划分待确认，但至少需要区分内容编辑和审核/发布操作，避免未经审核的内容进入用户端。

## 8. 核心数据对象

### 8.1 用户

- 用户 ID
- 微信身份关联信息
- 学习目标
- 创建时间和最近活跃时间
- 订阅消息授权状态

### 8.2 知识点

- 知识点 ID
- 所属考试、主题和章节
- 知识目标
- 难度
- 内容版本
- 来源信息
- 发布状态

### 8.3 知识卡

- 卡片 ID
- 关联知识点 ID
- 标题、结论、解释和例子
- 回忆提示/自测题
- 正确答案或参考答案
- 内容来源
- 审核人、审核时间和版本

### 8.4 学习记录

- 用户 ID
- 卡片 ID/知识点 ID
- 学习或复习时间
- 学习阶段
- 自评结果
- 客户端和内容版本信息

### 8.5 复习计划

- 用户 ID
- 知识点 ID
- 当前记忆阶段
- 下一次复习时间
- 最近一次复习结果
- 连续记住次数
- 算法版本

## 9. 页面与后台要求

### 9.1 用户端页面

- 登录/授权页
- 新手引导页
- 学习卡流页
- 记忆自评组件
- 待复习任务入口
- 复习提醒授权提示

首页是否需要单独展示学习统计、每日目标或其他导航内容，待确认；MVP 应优先保证用户能快速进入卡片和复习流程。

### 9.2 内容后台页面

- 内容列表页
- 卡片编辑页
- AI 生成结果页
- 审核页
- 发布/下架操作
- 版本和来源记录页

## 10. 埋点与验收

### 10.1 关键事件

- 小程序打开
- 微信登录成功
- 新手引导完成
- 第一张卡展示
- 卡片完成
- 上滑下一张
- 下滑返回
- 选择忘了/模糊/记住了
- 创建复习计划
- 进入到期复习
- 完成到期复习
- 订阅消息授权成功/拒绝
- 点击复习提醒
- 卡片错误/难懂/重复反馈（若首版启用）

### 10.2 MVP 验收条件

- 新用户可以完成登录、引导并进入第一张卡。
- 用户可以连续上下滑动浏览卡片，且返回上一张不会造成重复记账。
- 每张卡完成后可以选择三档记忆自评。
- 自评结果会保存，并生成可查询的下一次复习时间。
- 到期知识点可以在小程序内被识别并优先展示。
- 用户授权后可以收到微信订阅消息；拒绝授权不影响核心学习流程。
- 内容人员可以完成 AI 初稿生成、人工编辑、审核、发布和下架。
- 已发布卡片包含来源和版本信息，未审核卡片不会出现在用户端。
- 关键学习事件能够被记录，用于评估激活、完成和复习留存。

## 11. 非功能需求

- **性能**：卡片切换应保持流畅，避免每次滑动都出现明显等待。
- **稳定性**：网络波动时不能丢失已完成的自评结果；失败操作需要给出可理解的提示。
- **可读性**：适配常见手机屏幕和系统字体设置，保证正文、公式和关键词易读。
- **可访问性**：交互不能只依赖颜色表达状态；文字和点击区域应清晰。
- **隐私**：只收集完成学习、提醒和产品分析所需的数据，并提供必要的隐私说明。
- **内容安全**：对 AI 输出和后台发布流程设置人工审核和操作记录。
- **可追溯性**：卡片内容、来源、审核结果和复习算法都需要记录版本。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| CAPM 大纲或考试要求发生变化 | 内容可能过时 | 保存来源和版本，支持批量标记、复审和下架 |
| AI 生成事实错误或错误解释 | 误导备考者 | AI 只产出草稿，必须经过教研审核 |
| 版权或商标使用边界不清 | 内容和产品存在合规风险 | 仅使用有权使用的资料，记录来源，不宣称官方合作 |
| 用户只滑新卡、不做复习 | 学习效果下降 | 复习任务优先展示，并通过提醒引导回访 |
| 自评不准确 | 复习排期失真 | 解释三档含义，保留回顾和修正机制 |
| 微信订阅消息授权率低 | 主动提醒覆盖不足 | 保留小程序内到期任务入口，不依赖消息作为唯一入口 |
| 卡片过度压缩导致知识失真 | 用户形成错误理解 | 一个知识点可拆成多张卡，审核时检查上下文完整性 |

## 13. 待确认事项

以下事项不影响当前 MVP 方向，但在产品设计和技术设计前需要明确：

1. CAPM 首版具体覆盖哪些主题、章节和知识点；需要以哪一版官方大纲为准。
2. 首批内容数量和每个主题的覆盖深度。
3. 是否提供完整的章节导航，以及是否需要展示学习统计。
4. 间隔复习算法的具体实现、默认间隔和错过复习任务的处理方式。
5. 每日新卡数量、每日复习上限和用户是否可以自行调整。
6. 微信订阅消息的提醒时间、提醒频率和多任务合并规则。
7. 内容后台的具体使用人员、角色权限和审核流程。
8. AI 服务提供商、模型、调用成本、数据保留和敏感内容处理规则。
9. 首版是否需要卡片纠错反馈。
10. 产品是否需要收费、商业化和用户增长功能。
